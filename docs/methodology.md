# 数学原論　制作方法論

制定：2026-11-26（初期版）。

## 基本方針
ブルバキの構造的な思想を参照し、独立したノートではなく一つの数学体系として制作する。分野横断的な共通構成（部分・商・積・自由構成・普遍性等）を重視する。原論の全体構造は全順序ではなく、基礎から発展へ向かう有向非巡回グラフ（DAG）とする。分岐・合流を認め、知識の依存関係、ノート番号、制作順序を区別する。異なる枝の先行知識を不必要に要求しない。暫定案は確定規約と混同しない。

## 制作の手順
1. AGENTS.md、本書、docs/knowledge.md、docs/knowledge.json、関連原稿の最新版を読む。
2. 対象ノートの位置と、対象知識の直接前提・その推移閉包を確定する。無関係な先行ノートは前提としない。前提が未確定なら明示して草稿扱いとする。
3. 構成案を立て、導入する定義、公理、結果、構成と直接依存先を台帳に登録する。
4. 数学書調の厳密な原稿を執筆する。既出の結果は恒久IDと表示上の所在を用いて参照し、循環・先取り・暗黙の仮定を避ける。原稿を genron:begin/end で囲み、genron:use で直接依存を注釈する。
5. 各証明の論理、定義の適法性、仮定、記法の整合、依存関係、到達点を点検する。知識およびノートの両階層の依存グラフの循環、参照切れ、未確立事項の使用を検査する。`graph notes`、`graph knowledge`、`prerequisites ID` で構成を確認する。`node scripts/test-knowledge.mjs` と `node scripts/knowledge.mjs check` を実行し、正式版では `check --strict` を用いる。これらは無矛盾性の形式的証明を意味しない。
6. pLaTeX原稿では原則 platex 2回、dvipdfmx、ログ調査、全ページの目視確認を行う。実行不能ならpLaTeX原稿を保持し、未検証事項を報告する。XeLaTeXへの恒久置換は禁止。
7. 原稿と台帳の状態・到達点・依存関係を同期してコミットする。可能なら一つの変更単位にまとめ、複数コミットの場合は途中状態を草稿と扱う。
8. 作業中の添削・指摘から一般化できる規約を本書または対応する規約文書へ追記する。変更の理由と影響範囲を記す。数学的知識は必ず台帳を正本とする。
9. ユーザーに変更ファイル、コミット、検証結果、未実施事項、暫定判断を報告する。

## 組版・文体の暫定方針
従来の共通pLaTeXテンプレート第2版を参考に、A5判・本文10pt・装飾を抑えた硬質な数学書調を採用する方向とする。テンプレート実体や最終的な書式は未整備であり、確定時に記録する。厳密性をページ数より優先する。

## 改訂
原稿の修正に際して、`node scripts/knowledge.mjs impact ID...` または `impact --base COMMIT` で逆依存を調査し、影響を受ける結果・到達点を再検証する。変更の影響が不明な場合は要再検証とする。承認済みの規約の変更、基礎体系の変更など大きな決定は、暫定案と区別しユーザーの確認を得る。

台帳の正本は docs/knowledge.json とする。docs/knowledge.md は形式と運用規則のみを記述し、知識の二重管理をしない。

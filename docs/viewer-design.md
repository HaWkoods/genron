# 数学原論　検索・PDF閲覧サイトの設計

2026-11-27。初版実装を追加。公開状態・テスト結果は Actions と実際のサイトで確認する。

## 確定した閲覧方針

ノート名・知識項目名・記述・恒久IDを検索でき、原論専用のPDFビューアで該当箇所を閲覧できるようにする。定義・命題一覧PDFも閲覧対象とする。知識台帳を唯一の正本とし、原稿やページ番号の変更に対しても恒久IDで参照先を維持する。

本文中の明示的な定義・命題への参照では、クリックで参照先ノートの該当位置へ移動し、マウスホバーで仮定と記述を数式付きで表示する。Ctrl/Command+クリックで別タブ、戻る操作で元の閲覧位置を復元する。タッチ端末ではタップでプレビュー、プレビュー内のリンクで移動する方式を候補とする。

## プレビューの確定デザイン

ユーザーの選択：D案（可変型）、初期設定はC案相当。

| 項目 | 初期値・仕様 |
|---|---|
| 基準幅 | 580 CSS px |
| 内側余白 | 上下左右 28 CSS px |
| 幅の設定範囲 | 300–760 CSS px |
| 余白の設定範囲 | 12–40 CSS px |
| 高さ | 内容に応じて自動 |
| 最大高さ | 500 CSS px を初期上限の目安とし、画面の利用可能領域に応じて縮小 |
| 画面端 | 画面内へ位置調整し、狭い画面では幅も縮小 |
| 長い記述 | 縦方向の内部スクロールのみ。数式は行単位で折り返し、分割不能な数式が幅を超える場合だけ縮小 |
| ポインタ | 参照箇所からボックス内部へ移動しても表示を維持 |
| 内容 | ノート名、知識ID、種類・名称、仮定、記述、参照先リンク。証明・解説は追加しない |

幅と余白は読者が設定画面で変更できるようにする。ブラウザ内の設定保存、キーボードフォーカスからの表示、Escapeでの閉じる操作、画面端に応じた表示方向の変更は実装時の推奨仕様。画面が狭いときは設定値に固執せず読みやすさを優先する。数学的な内容の欠落や省略によってボックスを小さくしない。

## 実装方針

GitHub Pages、PDF.js、数式レンダラー（KaTeX又はMathJax）、pLaTeX/hyperrefによる恒久ID付きの移動先とリンク、知識台帳に基づく検索データの生成、GitHub Actionsによる同期を検討する。実装時にはライブラリの版、配信経路、PDFリンク注釈の形式、セキュリティ、実際のブラウザでの挙動を確認する。既存原稿の明示参照は段階的に改修し、定義の単なる出現や台帳の依存注釈だけを機械的に本文参照へ変換しない。知識台帳の記述がプレビューの出典であり、PDF本文からの逐語引用とは限らない。数学的内容を変更する必要が生じた場合は既存の改訂規約に従う。

## 初版の実装

- site/index.html、style.css、app.mjs：ノート・知識の検索、PDF.js の単頁ビューア、ページ移動・倍率、恒久IDへのジャンプ、戻る操作、ホバーとタッチ用プレビュー、幅・余白の保存。プレビューは KaTeX で台帳の記法を可能な範囲で組版し、変換不能な箇所は原記述を表示する。
- scripts/viewer-tex.mjs：公開時の原稿コピーに hyperref の named destination と URI リンクを埋め込む。正本のTeXや定理番号を改変しない。既存の同一ノート内の明示的な `\\ref{...}` と本文中の知識IDをリンク化する。選択公理の明示参照は名称を含めてリンク化する。他の自然言語の参照や単なる定義語の出現は自動認識しない。
- 新しい本文参照は、台帳登録済みの恒久IDを明記するか、既存の `\\ref` を用いる。専用命令 `\\GenronRef{K-番号}` / `\\GenronRefText{K-番号}{表示文字列}` も変換に対応するが、使用する原稿には通常のpLaTeX組版用のフォールバック定義（それぞれID、表示文字列を表示）と genron:use 注釈を設けること。後者の表示文字列は入れ子のないものとする。
- scripts/build-site.mjs：同じコミットの検証済み原稿・台帳から閲覧用PDFと公開検索データを生成し、全知識IDのPDF移動先及び実際の参照URIを検査する。台帳の査読記録などは検索データに含めない。PDF.js 4.10.38 と KaTeX 0.16.22 をサイト内に配布する。
- scripts/test-viewer-tex.mjs、scripts/test-viewer-browser.mjs：変換の単体テスト及びChromeによる実際の検索・PDF・ホバー操作のスモークテスト。
- .github/workflows/reader.yml：main の原稿・台帳・サイトの変更時に構築し、ブラウザ検査後、GitHub Pages 用成果物を作成する。GitHub Pages の Source は GitHub Actions を選択する必要がある。公開URLの予定は https://hawkoods.github.io/genron/ 。ビルド成功と公開成功は区別する。

ローカルでは Node.js 22、pLaTeX/dvipdfmx、poppler-utils、Chrome が必要。リポジトリの根で以下を実行する。

```sh
npm install --no-save --ignore-scripts --package-lock=false --omit=optional pdfjs-dist@4.10.38 katex@0.16.22 playwright-core@1.51.1
node scripts/test-viewer-tex.mjs
node scripts/build-site.mjs
node scripts/test-viewer-browser.mjs
python3 -m http.server 8000 --directory _site
```

公開サイトは `_site` のみから構成する。データ・PDFの更新はサイト構築時に同じ台帳の版から行う。GitHubに掲載する従来のPDFと、参照注釈を付したサイト用PDFは別の生成物とする。

## ページ送りの改善

2026-11-27：単頁ビューアで頁送りが困難との報告を受け、上部ツールバーを追従表示し、PDFの下にも前後頁ボタンと頁番号を設置する。ページ変更時は描画完了まで操作を無効化し、旧描画処理の競合を避ける。頁の切り替え後は新しい頁の先頭に移動する。前後ノート・前後知識項目への明示リンクも設ける。ブラウザテストはページ番号と実際のPDF描画の切り替えを検査する。報告された端末固有の原因は未特定。

### ページ送り不具合の原因と修正

ブラウザテストで `ReferenceError: turn is not defined` を再現した。ボタンのコールバックを作るスコープと、try ブロック内のページ送り函数のスコープが異なっていたことが原因。コールバックから参照可能なスコープにハンドラを保持し、PDF読み込み後に設定する。テストではブラウザの未捕捉エラーも失敗条件とする。`note` はノート番号、`page` はページ番号であり、`page` を省略した場合は1頁から表示する。

## 連続スクロール方式（2026-11-27）

ユーザーの指定により単頁表示を廃止し、全頁の枠を縦方向に配置する。ブラウザの通常のスクロールで読み進められることを正規の閲覧方式とする。表示中の頁と近傍だけを描画し、遠方の描画を解放する。上部の頁番号はスクロール位置と連動し、前後頁・頁番号指定はスクロール移動の補助操作とする。恒久IDによる定義・命題の位置へのジャンプ、リンク注釈、プレビュー、戻る操作と倍率変更を維持する。ノート本体と定義・命題一覧の双方に適用する。ブラウザテストではN-3の複数頁が縦に並び、ホイール操作のみで頁が進むことを確認する。

## 表示方式の選択（2026-11-27）

連続スクロールを初期値とし、閲覧画面の上部に「表示方式」選択欄を置く。「1ページずつ」に切り替えると現在頁だけを表示し、上部・下部の前後頁ボタンと頁番号入力で移動する。「連続スクロール」に戻すと全頁を縦に配置する。切替時の現在頁と頁内の相対的な閲覧位置を維持する。選択はブラウザの localStorage に保存し、ノート・定義命題一覧・再訪問に共通して適用する。ストレージが使えない場合は当該セッション内で維持する。両方式で同一の描画・リンク注釈・知識ID移動の処理を用い、別々の実装にしない。ブラウザテストで切替・頁送り・再読み込み・一覧PDF・知識IDジャンプを検証する。

## 分類・検索の再編（2026-11-27）

部・篇・ノート・知識の4分類に対応する。検索データは全計画ノート（状態・到達目標・直接前提・依存層・篇ID）と部篇分類を追加する。公開PDFと知識は従来どおり verified のみ。初期表示では部・篇の折りたたみ目次を掲げ、公開済みの部篇は展開する。検索は部・篇・ノート・知識の名称、ID、内容を対象とし、公開済み／制作予定／ノート／定義・命題に絞り込める。制作予定ノートは到達目標と直接前提を表示するが、未存在PDFへのリンクは作らない。着手可能なノートは全直接前提が検証済みの予定ノートとして機械的に抽出する。分類は依存関係と独立する。既存の閲覧モードと参照は保持する。

- 記号・記法一覧は docs/notation.tex と docs/notation.md に収録し、既出と先行規約を区別する。新規執筆前に照合し、改訂時は両方を同期する。先行記法は知識の導入を意味しない。閲覧室では ?note=notation により既存PDFビューアで表示する。

## 記号索引（第2版）

記号・対象名を各行に並べ、既出の項目は右列の対象名・説明文だけに知識IDのURI注釈を埋め込む。左列の記号はリンクにしない。ノートと同じホバー・クリック・履歴復元を共用する。先行記法には未定義の参照を設けない。ビルド時に公開済みIDとPDFの実際のURIを検査する。

記号一覧PDFは左列を記号（本文幅43%）、右列を対象・意味（53%）とする横並びの固定二列組版とし、列間は4%とする。各分野の冒頭に列見出しを置き、右列の長文は同じ列内で折り返す。長い数式は左列の幅以内に収める。既存の知識ID参照・ホバー・クリックを保持する。
各行の下に細い横罫を置く。未導入・先行の状態は記号台帳の id=null として管理し、公開PDF・Markdown・閲覧サイトには表示しない。公開画面に先行状態のラベルを追加しない。

## 参照プレビューの縦スクロール限定

プレビューボックス及び設定見本では横スクロールを廃止する。短い数式は通常のインライン数式として表示し、文章は折り返す。一つの数式が段落幅を超える場合は、内容を切り捨てず、その数式だけを幅内に縮小する。幅・余白設定、画面サイズ、フォント読み込みに応じて再計算する。長い定義はボックス全体の縦スクロールで読む。PDF本体の倍率・横方向移動の挙動は変更しない。

## 数学構造地図（2026-11-27）
公開検索データの plan の全ノートと depends_on を用い、前提から後続への有向辺を描く。論理的深さを縦軸、部・篇を横方向の帯として配置する。分類を頂点に縮約しない。検索・選択による配置変更は行わず、関連頂点の濃淡と視点を変更する。直接・推移関係、前提・後続・両方向、局所表示、前提集合のトポロジカル順（学習経路）、ズーム、ドラッグ、ミニマップ、目標と知識項目のプレビュー、公開PDFへのリンクを提供する。低倍率ではノート名を省略する。完成数は表示しない。新規ノート追加時は台帳から再配置されるため、版をまたぐ座標固定は保証しない。Canvasを用い外部ライブラリを追加しない。ブラウザ検証と公開はActionsで確認する。

## ノート統合時の互換性（2026-11-27）
台帳 note_aliases は旧番号・統合先・最初の知識ID・移動したID群を管理する。旧番号の通常URLは統合先の該当節を開く。page 指定の旧URL及び旧PDFの直接URLは archive/ の旧原稿から再生成したPDFを表示する。知識IDは新しい所在へ解決する。旧番号は総目次と構造地図から除き、旧番号で検索すると統合先を表示する。統合先の旧ページ番号は組版変更により移動し得る。番号付き知識参照を正規とする。

## 本文の参照知識の表示範囲

- 2026-11-27 ユーザー指定：Web本文の「参照する知識」は，個々の知識項目の依存DAGの層（最長前提経路の長さ）を用い，当該項目より1層又は2層前に属する直接依存項目のみを表示する．それ以前の直接依存は表示しない．表示対象が空なら欄を設けない．台帳・公開データの全依存辺，本文・証明中の明示参照，依存グラフ及び学習経路は変更しない．ノートの分類番号やノート計画の層と混同しない．

## 知識を起点とする関連ノート検索

- 2026-11-27 ユーザー指定：知識項目を検索して関係ノートのみを表示する専用ページ（`?view=knowledge-path`）を設ける．公開済みの定義・命題・公理を名称・番号・記述で検索し，選択した知識項目から全依存辺を前提方向・後続方向・両方向に探索する．直接・推移の切替を可能にする．探索後にノートへ射影して重複を除き，関係する知識項目だけを各ノート内に表示する．ノート計画上の依存は追加探索しない．本文中の参照知識欄の2層制限はこの探索に適用しない．ノートは計画DAGの層順に並べる．未制作の知識は検索対象外とする．

- 2026-11-27 ユーザー指定：知識からたどるノートの検索結果をリンク一覧ではなく，選択知識と接続するノートの全文を依存階層の浅い順に並べた連続閲覧ページとする．既定は全文表示とし，関連知識のみの本文表示にも切替可能とする．対象ノートの選択知識を識別できる表示とノート内目次を設ける．依存探索と対象ノート集合は従来どおり知識DAGから計算し，全文表示によって追加された無関係な知識を探索対象に加えない．各ノート内は原稿順，証明・解答の開閉，明示参照，参照知識欄の2層制限は通常閲覧と共通の処理を用いる．

- 2026-11-27 ユーザー指定：知識からたどるノートでは，ノートの依存階層番号について昇順（既定）・降順を選択可能とする．目次と本文の並び順を同期し，同一階層内は恒久ノート番号の昇順を維持する．ノート内部の原稿順と関連ノートの集合は変更しない．降順は `order=desc` でURLに保存する．
